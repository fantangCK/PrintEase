# 小程序开发指南

本文档集成了自助打印小程序的前端逻辑、下单流程、支付处理以及商户端功能的开发指南。

# 第一部分：下单流程文档

## 一、概述

本文档详细介绍 PrintEase 小程序的完整下单流程，包括文件上传、转换、价格计算、订单创建等环节。

---

## 二、完整下单流程

### 2.1 流程总览

```
用户进入小程序
    ↓
选择文件上传
    ↓
文件格式检查
    ↓
如需转换 → 发送转换请求 → 等待转换完成
    ↓
无需转换（PDF）
    ↓
进入订单创建页面
    ↓
选择打印参数（份数、颜色、单双面等）
    ↓
实时计算价格
    ↓
填写备注（可选）
    ↓
确认创建订单
    ↓
跳转支付选择页面（支持微信和支付宝）
    ↓
选择支付方式
    ↓
跳转到支付页面
    ↓
支付完成 → 订单状态变为「待打印」
```

---

### 2.2 文件上传流程

#### 2.2.1 支持的文件格式
- **可直接打印**：PDF
- **需转换**：DOC, DOCX, XLS, XLSX, PPT, PPTX, TXT, JPG, PNG 等

#### 2.2 文件上传步骤
1. 用户在上传页面选择本地文件
2. 前端调用文件上传接口 `/api/files/upload?fileName=xxx`
   - 使用 `encodeURIComponent` 编码原始文件名作为查询参数
3. 后端接收文件并保存到服务器，优先使用原始文件名
   - 如果文件名重复，自动添加数字后缀
4. 后端返回文件信息（包括文件 ID、原始文件名、文件大小、页数等）
5. 前端显示文件信息，保持原始文件名显示
6. 前端检查文件类型，如果不是 PDF 则显示转换按钮

#### 2.2.3 文件信息字段
```typescript
{
  id: number;              // 文件 ID
  fileName: string;        // 原始文件名
  filePath: string;        // 文件存储路径
  fileSize: number;        // 文件大小（字节）
  fileType: string;        // MIME 类型
  fileExt: string;         // 文件扩展名
  totalPages?: number;     // 总页数（PDF/DOC等）
  convertedPdfPath?: string; // 转换后 PDF 路径
}
```

---

### 2.3 文件转换流程

#### 2.3.1 转换触发条件
- 文件扩展名不是 `.pdf`
- 用户点击「转换为 PDF」按钮

#### 2.3.2 转换步骤
1. 前端调用文件转换接口
2. 后端将转换任务加入队列
3. 前端轮询转换状态或通过 WebSocket 接收进度
4. 转换完成后，后端更新文件信息，添加 `convertedPdfPath` 字段
5. 前端显示转换完成，可继续下单

#### 2.3.3 转换状态
- `pending`: 等待转换
- `converting`: 转换中
- `completed`: 转换完成
- `failed`: 转换失败

### 2.4 价格计算逻辑

#### 2.4.1 价格配置（从数据库获取）
系统支持四种价格配置：
| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| blackWhiteSingleSidedPrice | 黑白单面价格/页 | 0.1 元 |
| blackWhiteDoubleSidedPrice | 黑白双面价格/页 | 0.08 元 |
| colorSingleSidedPrice | 彩色单面价格/页 | 0.5 元 |
| colorDoubleSidedPrice | 彩色双面价格/页 | 0.4 元 |
| minPrice | 最低消费 | 0 元（无最低消费） |

**重要**：价格配置优先从数据库加载，不使用前端默认值。

#### 2.4.2 价格计算公式

1. **确定单价**：
   - 根据用户选择的 `color_type`（0=黑白，1=彩色）和 `double_sided`（0=单面，1=双面）确定单价
   - 黑白单面 → `blackWhiteSingleSidedPrice`
   - 黑白双面 → `blackWhiteDoubleSidedPrice`
   - 彩色单面 → `colorSingleSidedPrice`
   - 彩色双面 → `colorDoubleSidedPrice`

2. **计算页数**：
   - 如果是双面打印，页数向上取整到偶数
   - 例如：3 页双面 → 按 4 页计算

3. **计算总价**：
   ```
   总价 = 单价 × 页数 × 份数
   ```

4. **应用最低消费**（已取消）：
   - 如总价 < 最低消费，按最低消费计算
   - 目前最低消费设为 0，即无限制

#### 2.4.3 价格计算示例
- 文件：5 页
- 选择：黑白双面，2 份
- 计算：
  - 单价：0.08 元/页
  - 页数：5 页（双面，不满双数按双数计算 → 6 页）
  - 总价：0.08 × 6 × 2 = 0.96 元

### 2.5 订单创建流程

#### 2.5.1 订单创建接口
- **路径**：`POST /api/orders`
- **请求参数**：
```typescript
{
  fileIds: number[];         // 文件 ID 列表
  copies: number;             // 打印份数
  paperSize: string;          // 纸张大小（A4/A5/A3）
  colorType: number;          // 颜色类型（0=黑白，1=彩色）
  doubleSided: number;        // 双面打印（0=单面，1=双面）
  printQuality: string;       // 打印质量（draft/normal/high）
  remark?: string;            // 备注（可选）
  deliveryAddress?: string;   // 派送地址（可选）
  deliveryTime?: string;      // 派送时间（可选）
}
```

#### 2.5.2 订单创建步骤
1. 用户在订单创建页面填写打印参数
2. 前端实时计算并显示预估价格
3. 用户点击「确认下单」
4. 前端调用订单创建接口
5. 后端验证参数并创建订单
6. 后端返回订单信息（包括订单号、总金额等）
7. 前端跳转到支付页面

#### 2.5.3 订单状态
| 值 | 说明 |
|----|------|
| 0 | 待支付 |
| 1 | 待打印/待接单 |
| 2 | 打印中 |
| 3 | 已打印 |
| 4 | 已完成 |
| 5 | 已取消 |
| 6 | 已失败 |

#### 2.5.4 订单权限控制
系统实现了完整的订单权限控制机制：

**用户权限**：
- 普通用户只能查看和操作自己的订单
- 无法查看其他用户的订单
- 可以取消自己的待支付订单

**商户权限**：
- 商户可以查看所有待接单的订单（可按楼栋筛选）
- 商户可以查看和操作分配给自己的订单
- 可以查看订单详情、开始打印、完成打印等操作
- 商户登录后使用独立的 `merchantToken` 或 `apiKey` 进行认证

**管理员权限**：
- 管理员可以查看和操作所有订单
- 可以强制设置订单状态
- 可以删除订单
- 管理员登录后使用 `adminToken` 进行认证

**订单详情接口权限**：
- 后端 `GET /orders/:id` 接口支持三种角色访问：
  1. 普通用户：只能访问自己的订单
  2. 商户：可以访问分配给自己的订单
  3. 管理员：可以访问所有订单

#### 2.5.5 订单自动取消
系统会自动取消超过一天的待支付订单：
- 每天凌晨 1 点执行检查
- 检查所有状态为「待支付」且创建时间超过 24 小时的订单
- 自动将订单状态更新为「已取消」
- 用户可在订单列表中看到已取消的订单
- 管理员也可在后台查看已取消订单，方便对账退款

### 2.6 文件预览功能

#### 2.6.1 预览时机
- **上传前**：已取消（避免不必要的预览）
- **转换后**：在订单创建页面和订单详情页面显示预览
- **订单列表**：在待打印订单页面显示预览

#### 2.6.2 预览文件选择
- 如果文件已转换（`convertedPdfPath` 存在），使用转换后的 PDF
- 否则使用原始文件（仅 PDF）

#### 2.6.3 预览方式
- 小程序中使用 `uni.openDocument` 打开 PDF 文件
- 需先通过 `uni.downloadFile` 下载文件到本地

# 第二部分：支付订单复用 - 前端处理逻辑

## 概述

本文档描述了 PrintEase 印易项目中支付订单复用的前端处理逻辑。

**重要说明：支付订单复用的核心逻辑完全在后端实现，前端代码不需要做任何修改！**

## 前端工作流程

### 完整支付流程

```
用户在订单详情页点击"立即支付"
        ↓
前端调用 createPayment API
        ↓
    后端处理（复用或创建新支付）
        ↓
后端返回 payUrl 和 tradeNo
        ↓
前端跳转到支付页面
        ↓
展示支付二维码
        ↓
用户扫码支付
        ↓
用户点击"我已支付"查询状态
        ↓
轮询或刷新订单状态
```

## 涉及的前端文件

### 1. 订单详情页 (`pages/order/detail.vue`)

**核心功能：**
- 展示订单信息
- 提供"立即支付"按钮
- 提供"刷新订单状态"按钮

**关键代码片段：**

```typescript
async function goToPay() {
  if (!order.value) return
  
  try {
    uni.showLoading({ title: '创建支付中...' })
    // 调用后端 API
    const result = await createPayment(orderId.value)
    uni.hideLoading()
    
    if (result.payUrl) {
      // 跳转到支付页面
      uni.navigateTo({
        url: `/pages/pay/index?payUrl=${encodeURIComponent(result.payUrl)}&orderId=${orderId.value}`
      })
    }
  } catch (error) {
    uni.hideLoading()
    console.error('创建支付失败', error)
    uni.showToast({
      title: '创建支付失败',
      icon: 'none'
    })
  }
}
```

### 2. 支付页面 (`pages/pay/index.vue`)

**核心功能：**
- 展示支付二维码
- 提供"打开支付页面"按钮

**关键代码片段：**

```typescript
function openPayPage() {

function checkPaymentStatus() {
  if (!orderId.value) return
  
  uni.showLoading({ title: '查询中...' })
  
  // 调用后端 API 刷新订单状态
  refreshOrderStatus(orderId.value).then((result) => {
    uni.hideLoading()

      uni.showToast({

        uni.navigateBack()

      uni.showToast({
        title: '尚未检测到支付，请稍后再试',
        icon: 'none'
      })
    } else {
      uni.showToast({
        title: '订单状态已变更',
        icon: 'none'
      })
      setTimeout(() => {
        uni.navigateBack()
      }, 1500)
    }
  }).catch(() => {
    uni.hideLoading()
    uni.showToast({
      title: '查询失败',
      icon: 'none'
    })
  })
}
```

### 3. API 接口文件 (`api/order.ts`)

**关键接口：**

```typescript
// 创建支付
export function createPayment(orderId: string) {
  return request<{ tradeNo: string; payUrl: string }>({
    url: `/orders/${orderId}/payment`,
    method: 'POST'
  })
}

// 刷新订单状态
export function refreshOrderStatus(orderId: string) {
  return request<OrderInfo>({
    url: `/orders/${orderId}/status`,
    method: 'POST'
  })
}
```

### 1. 逻辑透明性

# 第三部分：小程序前端逻辑汇总

## 二、商户端逻辑 (已实现)

### 2.1 入口
- 商户通过独立的登录页面进行登录
- 商户登录后使用 `merchantToken` 或 `merchantApiKey` 进行认证
- 商户端页面位于 `pages/merchant/*` 目录下

### 2.2 商户端页面
- **商户登录页** (`pages/merchant/login.vue`): 商户手机号密码登录
- **商户首页** (`pages/merchant/index.vue`): 商户工作台，显示统计信息
- **接单大厅** (`pages/merchant/grab-orders.vue`): 展示待接单的订单，商户可以抢单
- **我的订单** (`pages/merchant/my-orders.vue`): 查看已接单的任务，管理订单状态
- **商户设置** (`pages/merchant/settings.vue`): 商户信息管理
- **上传派送** (`pages/merchant/upload-delivery.vue`): 上传派送完成图片

### 2.3 商户认证方式
商户有两种认证方式：

**方式1：JWT Token (小程序使用)**
- 商户通过手机号和密码登录
- 获取 `merchantToken` 并存入 Storage
- 请求时在 Header 中添加 `Authorization: Bearer ${merchantToken}`

**方式2：API Key (独立客户端使用)**
- 商户创建时自动生成 32 字节十六进制 API Key
- 请求时在 Header 中添加 `x-api-key: ${apiKey}`

### 2.4 商户端功能

#### 2.4.1 接单大厅
- 展示所有待接单的订单（状态=1）
- 支持按楼栋筛选订单
- 显示订单基本信息（订单号、时间、位置、页数、金额）
- 提供"接单"按钮，点击后弹出确认框
- 接单成功后订单状态变为"打印中"(2)
- 订单绑定到当前商户

#### 2.4.2 订单管理
- 查看已接单的任务列表
- 支持按订单状态筛选
- 查看订单详情和文件信息
- 提供订单状态操作按钮

#### 2.4.3 打印任务操作
商户可以对订单进行以下操作：

**单个打印任务操作**：
- `开始打印`: 更新任务状态为"打印中"
- `完成打印`: 更新任务状态为"已完成"
- `强制完成`: 强制完成打印任务并同步订单状态
- `重新下发`: 重新下发打印任务
- `标记失败`: 标记打印任务失败

**订单级操作**：
- `开始订单的所有打印任务`: 一键开始该订单的所有打印任务
- `强制完成订单的所有打印任务`: 一键强制完成该订单的所有打印任务
- `完成订单`: 标记订单为已完成

#### 2.4.4 派送管理
- 上传派送完成图片（支持文件上传和URL方式）
- 图片存储在 `uploads/delivery/` 目录
- 上传成功后订单状态更新为"已完成"

#### 2.4.5 商户信息管理
- 查看商户基本信息
- 更新商户地址、负责楼栋等信息
- 绑定/解绑微信账号
- 查看商户统计数据（待处理、处理中、今日完成）

### 2.6 订单文件结构说明
系统支持一个订单包含多个文件：
- 每个订单可以包含多个文件（OrderFile）
- 每个文件都有独立的打印参数（份数、颜色、单双面、纸张大小等）
- 每个文件对应一个打印任务（PrintTask）
- 订单级打印参数已保留用于兼容旧数据，但新订单不再使用

## 三、支付选择页面
### 3.1 支付方式选择
- 用户在订单创建后会跳转到支付选择页面
- 支持微信支付和支付宝支付
- 支付页面会根据用户选择动态显示相应的支付方式
- 支付宝支付开关默认开启

### 3.2 支付流程
1. 点击「确认下单」后跳转至支付选择页面
2. 选择微信支付或支付宝支付
3. 跳转至对应的支付页面
4. 支付完成后订单状态更新为「待打印」

## 四、注意事项
1. **Token 管理**: 登录后将 Token 存入 Storage，请求拦截器自动添加 Header。
2. **文件大小**: 限制上传文件大小 (推荐 50MB)，超大文件提示用户。
3. **轮询优化**: 避免过高频率轮询订单状态，建议使用 WebSocket 或长轮询 (待实现)。
4. **文件名显示**: 前端始终使用原始文件名显示，不显示临时文件名。
