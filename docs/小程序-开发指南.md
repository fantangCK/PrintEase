# 小程序开发指南

本文档集成了自助打印小程序的前端逻辑、下单流程、支付处理以及商户端功能的开发指南。

---

# 第一部分：下单流程文档

## 一、概述

本文档详细介绍 PrintEase 小程序的完整下单流程，包括文件上传、转换、价格计算、订单创建等环节。

---

## 二、完整下单流程

### 2.1 流程总览

```
用户进入小程序
    ↓
选择文件上传
    ↓
文件格式检查
    ↓
如需转换 → 发送转换请求 → 等待转换完成
    ↓
无需转换（PDF）
    ↓
进入订单创建页面
    ↓
选择打印参数（份数、颜色、单双面等）
    ↓
实时计算价格
    ↓
填写备注（可选）
    ↓
确认创建订单
    ↓
跳转支付页面
    ↓
支付完成 → 订单状态变为「待打印」
```

---

### 2.2 文件上传流程

#### 2.2.1 支持的文件格式
- **可直接打印**：PDF
- **需转换**：DOC, DOCX, XLS, XLSX, PPT, PPTX, TXT, JPG, PNG 等

#### 2.2.2 文件上传步骤
1. 用户在上传页面选择本地文件
2. 前端调用文件上传接口 `/api/files/upload`
3. 后端接收文件并保存到服务器
4. 后端返回文件信息（包括文件 ID、文件名、文件大小、页数等）
5. 前端检查文件类型，如果不是 PDF 则显示转换按钮

#### 2.2.3 文件信息字段
```typescript
{
  id: number;              // 文件 ID
  fileName: string;        // 原始文件名
  filePath: string;        // 文件存储路径
  fileSize: number;        // 文件大小（字节）
  fileType: string;        // MIME 类型
  fileExt: string;         // 文件扩展名
  totalPages?: number;     // 总页数（PDF/DOC等）
  convertedPdfPath?: string; // 转换后 PDF 路径
}
```

---

### 2.3 文件转换流程

#### 2.3.1 转换触发条件
- 文件扩展名不是 `.pdf`
- 用户点击「转换为 PDF」按钮

#### 2.3.2 转换步骤
1. 前端调用文件转换接口
2. 后端将转换任务加入队列
3. 前端轮询转换状态或通过 WebSocket 接收进度
4. 转换完成后，后端更新文件信息，添加 `convertedPdfPath` 字段
5. 前端显示转换完成，可继续下单

#### 2.3.3 转换状态
- `pending`: 等待转换
- `converting`: 转换中
- `completed`: 转换完成
- `failed`: 转换失败

---

### 2.4 价格计算逻辑

#### 2.4.1 价格配置（从数据库获取）
系统支持四种价格配置：
| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| blackWhiteSingleSidedPrice | 黑白单面价格/页 | 0.1 元 |
| blackWhiteDoubleSidedPrice | 黑白双面价格/页 | 0.08 元 |
| colorSingleSidedPrice | 彩色单面价格/页 | 0.5 元 |
| colorDoubleSidedPrice | 彩色双面价格/页 | 0.4 元 |
| minPrice | 最低消费 | 0 元（无最低消费） |

**重要**：价格配置优先从数据库加载，不使用前端默认值。

#### 2.4.2 价格计算公式

1. **确定单价**：
   - 根据用户选择的 `color_type`（0=黑白，1=彩色）和 `double_sided`（0=单面，1=双面）确定单价
   - 黑白单面 → `blackWhiteSingleSidedPrice`
   - 黑白双面 → `blackWhiteDoubleSidedPrice`
   - 彩色单面 → `colorSingleSidedPrice`
   - 彩色双面 → `colorDoubleSidedPrice`

2. **计算页数**：
   - 如果是双面打印，页数向上取整到偶数
   - 例如：3 页双面 → 按 4 页计算

3. **计算总价**：
   ```
   总价 = 单价 × 页数 × 份数
   ```

4. **应用最低消费**（已取消）：
   - 如总价 < 最低消费，按最低消费计算
   - 目前最低消费设为 0，即无限制

#### 2.4.3 价格计算示例
- 文件：5 页
- 选择：黑白双面，2 份
- 计算：
  - 单价：0.08 元/页
  - 页数：5 页（双面，不满双数按双数计算 → 6 页）
  - 总价：0.08 × 6 × 2 = 0.96 元

### 2.5 订单创建流程

#### 2.5.1 订单创建接口
- **路径**：`POST /api/orders`
- **请求参数**：
```typescript
{
  fileIds: number[];         // 文件 ID 列表
  copies: number;             // 打印份数
  paperSize: string;          // 纸张大小（A4/A5/A3）
  colorType: number;          // 颜色类型（0=黑白，1=彩色）
  doubleSided: number;        // 双面打印（0=单面，1=双面）
  printQuality: string;       // 打印质量（draft/normal/high）
  remark?: string;            // 备注（可选）
  deliveryAddress?: string;   // 派送地址（可选）
  deliveryTime?: string;      // 派送时间（可选）
}
```

#### 2.5.2 订单创建步骤
1. 用户在订单创建页面填写打印参数
2. 前端实时计算并显示预估价格
3. 用户点击「确认下单」
4. 前端调用订单创建接口
5. 后端验证参数并创建订单
6. 后端返回订单信息（包括订单号、总金额等）
7. 前端跳转到支付页面

#### 2.5.3 订单状态
| 值 | 说明 |
|----|------|
| 0 | 待支付 |
| 1 | 待打印 |
| 2 | 打印中 |
| 3 | 已完成 |
| 4 | 已取消 |
| 5 | 已失败 |

---

### 2.6 文件预览功能

#### 2.6.1 预览时机
- **上传前**：已取消（避免不必要的预览）
- **转换后**：在订单创建页面和订单详情页面显示预览
- **订单列表**：在待打印订单页面显示预览

#### 2.6.2 预览文件选择
- 如果文件已转换（`convertedPdfPath` 存在），使用转换后的 PDF
- 否则使用原始文件（仅 PDF）

#### 2.6.3 预览方式
- 小程序中使用 `uni.openDocument` 打开 PDF 文件
- 需先通过 `uni.downloadFile` 下载文件到本地

# 第二部分：支付订单复用 - 前端处理逻辑

## 概述

本文档描述了 PrintEase 印易项目中支付订单复用的前端处理逻辑。

**重要说明：支付订单复用的核心逻辑完全在后端实现，前端代码不需要做任何修改！**

## 前端工作流程

### 完整支付流程

```
用户在订单详情页点击"立即支付"
        ↓
前端调用 createPayment API
        ↓
    后端处理（复用或创建新支付）
        ↓
后端返回 payUrl 和 tradeNo
        ↓
前端跳转到支付页面
        ↓
展示支付二维码
        ↓
用户扫码支付
        ↓
用户点击"我已支付"查询状态
        ↓
轮询或刷新订单状态
```

## 涉及的前端文件

### 1. 订单详情页 (`pages/order/detail.vue`)

**核心功能：**
- 展示订单信息
- 提供"立即支付"按钮
- 提供"刷新订单状态"按钮

**关键代码片段：**

```typescript
async function goToPay() {
  if (!order.value) return
  
  try {
    uni.showLoading({ title: '创建支付中...' })
    // 调用后端 API
    const result = await createPayment(orderId.value)
    uni.hideLoading()
    
    if (result.payUrl) {
      // 跳转到支付页面
      uni.navigateTo({
        url: `/pages/pay/index?payUrl=${encodeURIComponent(result.payUrl)}&orderId=${orderId.value}`
      })
    }
  } catch (error) {
    uni.hideLoading()
    console.error('创建支付失败', error)
    uni.showToast({
      title: '创建支付失败',
      icon: 'none'
    })
  }
}
```

### 2. 支付页面 (`pages/pay/index.vue`)

**核心功能：**
- 展示支付二维码
- 提供"打开支付页面"按钮
- 提供"我已支付，查询状态"按钮

**关键代码片段：**

```typescript
function openPayPage() {
  if (!payUrl.value) return
  
  // 打开支付页面 webview
  uni.navigateTo({
    url: `/pages/webview/index?url=${encodeURIComponent(payUrl.value)}&orderId=${orderId.value}`
  })
}

function checkPaymentStatus() {
  if (!orderId.value) return
  
  uni.showLoading({ title: '查询中...' })
  
  // 调用后端 API 刷新订单状态
  refreshOrderStatus(orderId.value).then((result) => {
    uni.hideLoading()
    
    if (result.status === 1) {
      uni.showToast({
        title: '支付成功！',
        icon: 'success'
      })
      setTimeout(() => {
        uni.navigateBack()
      }, 1500)
    } else if (result.status === 0) {
      uni.showToast({
        title: '尚未检测到支付，请稍后再试',
        icon: 'none'
      })
    } else {
      uni.showToast({
        title: '订单状态已变更',
        icon: 'none'
      })
      setTimeout(() => {
        uni.navigateBack()
      }, 1500)
    }
  }).catch(() => {
    uni.hideLoading()
    uni.showToast({
      title: '查询失败',
      icon: 'none'
    })
  })
}
```

### 3. API 接口文件 (`api/order.ts`)

**关键接口：**

```typescript
// 创建支付
export function createPayment(orderId: string) {
  return request<{ tradeNo: string; payUrl: string }>({
    url: `/orders/${orderId}/payment`,
    method: 'POST'
  })
}

// 刷新订单状态
export function refreshOrderStatus(orderId: string) {
  return request<OrderInfo>({
    url: `/orders/${orderId}/status`,
    method: 'POST'
  })
}
```

## 为什么前端不需要修改

### 1. 逻辑透明性

- 支付订单复用逻辑完全在后端处理
- 前端只负责调用 API 和展示结果
- 后端返回的数据格式保持不变

### 2. API 接口不变

- 创建支付接口：`POST /api/orders/:id/payment`
- 返回格式：`{ tradeNo: string; payUrl: string }`
- 前端无需关心后端是复用还是新创建

### 3. 用户体验一致

- 用户操作流程不变
- 支付页面展示不变
- 状态查询方式不变

## 注意事项

### 1. 无需前端修改

- 支付订单复用是后端优化
- 前端代码保持原样
- 无需重新编译或发布前端

### 2. API 调用时机

- 每次用户点击"立即支付"都会调用后端 API
- 后端会自动判断是复用还是创建新支付
- 前端不需要做任何缓存或状态管理

### 3. 错误处理

4. 确认创建了新的支付信息

# 第三部分：小程序前端逻辑汇总

## 一、文件上传与预览
- **逻辑**:
  - 优先使用后端返回的 `convertedPdfPath`。
  - 使用 `uni.downloadFile` + `uni.openDocument` 实现预览。
  - 下载链接需包含 `/api` 前缀且为 HTTP/HTTPS 协议。

## 二、商户端逻辑 (规划)

### 2.1 入口
- 在"我的"页面，根据用户 `role` 字段判断。
- `role=1` (商户) 或 `role=2` (管理员) 显示"商户中心"入口。

### 2.2 功能
- **抢单大厅**: 轮询/WebSocket 获取待接单订单。
- **订单管理**: 查看已接单任务，上传完成照片。
- **状态更新**: 点击"开始打印"、"完成打印"。

## 三、注意事项
1. **Token 管理**: 登录后将 Token 存入 Storage，请求拦截器自动添加 Header。
2. **文件大小**: 限制上传文件大小 (推荐 50MB)，超大文件提示用户。
3. **轮询优化**: 避免过高频率轮询订单状态，建议使用 WebSocket 或长轮询 (待实现)。
