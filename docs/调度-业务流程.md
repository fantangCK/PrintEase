# PrintEase 印易 - 调度与业务流程文档

本文档详细描述了 PrintEase 系统中的调度机制，包含**业务调度**（商户接单/派单）和**技术调度**（云印节点/自动打印）。

---

# 第一部分：业务调度流程 (商户接单)

## 1. 业务模式概述
本项目正在从纯"自助打印"向"外卖接单模式"转型，引入商户角色。

### 1.1 角色定义
- **用户**: 发布打印需求 (下单)。
- **商户**: 拥有打印设备，接单并提供服务。
- **管理员**: 监管平台，配置价格，处理纠纷，拥有最高调度权。

### 1.2 订单流转状态机
```
[待支付] --支付成功--> [待接单] --商户接单--> [打印中] --打印完成--> [已完成]
                       |
                [已取消] <--用户取消/超时-->
```

## 2. 订单分配逻辑

### 2.1 接单模式 (主要)

商户可以主动接取未分配的订单。

*   **订单池**: 所有支付成功的订单进入 "待接单" 池。
*   **展示**: 商户端展示所有待接单的订单（可按楼栋筛选）。
*   **接单**: 商户点击 "接单"，系统检查订单状态并绑定商户 ID。
*   **归属**: 接单成功后，订单状态变更，生成打印任务归属于该商户。

### 2.2 派单模式 (辅助)
- **场景**: 订单长时间无人接单，或指定商户服务。
- **操作**: 管理员在后台手动将订单分配给指定商户。
- **通知**: 系统推送通知给被指派的商户。

## 3. 商户作业流程

### 3.1 接单前
- 需通过资质审核 (营业执照、设备信息)。
- 保持在线状态 (通过心跳或 WebSocket)。

### 3.2 接单后
1. **下载文件**: 从订单详情下载用户上传的文件 (PDF)。
2. **打印**: 使用本地设备打印。
3. **状态更新**: 
   - 点击"开始打印"更新任务状态为"打印中"
   - 点击"完成打印"更新任务状态为"已完成"
4. **订单流转**: 订单状态从"待接单"(1) → "打印中"(2) → "已完成"(3)

# 第二部分：技术调度架构 (Dispatch 模块)

此部分对应后端 `src/modules/dispatch` 模块及 `PrintEase-dispatch` 客户端的实现。

## 1. 模块职责
- **节点管理**: 打印节点注册、认证、心跳保活。
- **任务调度**: 轮询获取待打印任务，分配给指定节点。
- **状态追踪**: 监控打印任务状态 (下载中、打印中、完成、失败)。
- **跨平台支持**: 支持 Windows、Linux、macOS 的系统打印调用。

## 2. 系统架构

```
                        ┌─────────────────┐
                        │  云印调度客户端   │
                        │(PrintEase-dispatch)│
                        ├─────────────────┤
                        │ - 跨平台支持     │
                        │ - 轮询后端       │
                        │ - 下载文件       │
                        │ - 系统打印API    │
                        │ - 状态上报       │
                        └─────────────────┘
                                 ▲
                                 │ HTTP / WebSocket
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│                        印易后台 (Dispatch Module)                  │
├─────────────────────────────────────────────────────────────────┤
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    │
│  │  节点控制器   │    │  任务控制器   │    │  调度服务     │    │
│  │ (NodeCtrl)   │    │ (TaskCtrl)   │    │ (DispatchSvc)│    │
│  └──────────────┘    └──────────────┘    └──────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 核心流程设计

### 3.1 节点注册与保活
1. **注册**: 客户端启动时，向后端发送注册请求 (包含机器名、OS信息、打印机列表)。
2. **认证**: 后端返回 `node_key` 或 `token`。
3. **心跳**: 客户端每 30 秒发送一次心跳，汇报在线状态。
4. **离线判定**: 超过 3 个心跳周期未收到心跳，标记节点为离线。

### 3.2 任务轮询与执行
1. **轮询**: 客户端定期 (如 5秒) 请求 `/api/dispatch/tasks/poll`。
2. **认领**: 后端返回待打印任务，客户端确认接收。
3. **下载**: 客户端下载任务对应的 PDF 文件。
4. **打印**: 客户端调用本地 OS 打印 API (如 Windows Win32 Print, Linux CUPS)。
5. **上报**: 
   - 开始打印 -> 上报 `PRINTING`
   - 打印完成 -> 上报 `COMPLETED`
   - 出错 -> 上报 `FAILED` (附带错误信息)

## 4. 数据库设计 (Dispatch 相关)

### 4.1 云印调度节点表 (dispatch_nodes)
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | INT | 节点ID |
| node_name | VARCHAR | 节点名称 |
| node_key | VARCHAR | 认证密钥 |
| status | TINYINT | 状态 (0:离线, 1:在线) |
| os_type | VARCHAR | 操作系统 (windows/linux/macos) |
| printers | JSON | 可用打印机列表 |
| last_heartbeat | DATETIME | 最后心跳时间 |

### 4.2 打印任务表 (print_tasks)
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | VARCHAR | 任务ID |
| order_id | VARCHAR | 关联订单ID |
| node_id | INT | 分配的节点ID |
| file_id | INT | 文件ID |
| print_params | JSON | 打印参数 (份数、单双面等) |
| status | TINYINT | 状态 (待分配/已分配/打印中/完成/失败) |
| error_msg | TEXT | 错误信息 |

## 5. 跨平台打印实现方案

### 5.1 Windows
- 使用 `pywin32` 或 `win32print` 库。
- 调用 Windows Spooler API 发送 Raw 数据或 PDF 文件。

### 5.2 Linux / macOS
- 使用 `CUPS` (Common Unix Printing System)。
- Python 库: `pycups`。
- 命令行回退: `lp` 或 `lpr` 命令。

## 6. API 接口设计

### 6.1 商户任务相关
- `GET /api/merchant/tasks/unassigned`: 获取待接单列表
- `POST /api/merchant/tasks/:id/grab`: 商户接单
- `POST /api/merchant/tasks/:id/cancel`: 取消接单
- `PUT /api/merchant/tasks/:id/start`: 开始打印
- `PUT /api/merchant/tasks/:id/complete`: 完成打印
