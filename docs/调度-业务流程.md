# PrintEase 印易 - 调度与业务流程文档

本文档详细描述了 PrintEase 系统中的调度机制，包含**业务调度**（商户接单/派单）和**技术调度**（云印节点/自动打印）。

---

# 第一部分：业务调度流程 (商户接单)

## 1. 业务模式概述
本项目已从纯"自助打印"向"外卖接单模式"转型，引入商户角色。

### 1.1 角色定义
- **用户**: 发布打印需求 (下单)。
- **商户**: 拥有打印设备，接单并提供服务。
- **管理员**: 监管平台，配置价格，处理纠纷，拥有最高调度权。

### 1.2 订单流转状态机
```
[待支付] --支付成功--> [待接单] --商户接单--> [打印中] --打印完成--> [已完成]
                       |
                [已取消] &lt;--用户取消/超时/系统自动取消--&gt;
```

### 1.3 订单自动取消定时任务
系统实现了订单自动取消功能，定期清理超时未支付的订单：

**功能概述**：
- 每天凌晨 1 点执行订单过期检查
- 自动取消超过 24 小时的待支付订单
- 将订单状态更新为「已取消」(status = 4)
- 方便用户和管理员查看已取消订单

**技术实现**：
- 使用 `@nestjs/schedule` 库实现定时任务
- 定时任务服务位于 `src/modules/order/order-scheduler.service.ts`
- 使用 Cron 表达式 `0 1 * * *` 表示每天 01:00 执行

**订单取消逻辑**：
1. 查询所有状态为「待支付」(status = 0) 的订单
2. 使用 TypeORM 的 `LessThan` 查询创建时间超过 24 小时的订单
3. 批量更新订单状态为「已取消」
4. 记录日志，包含取消的订单数量

**管理员对账**：
- 管理员后台可以查看所有已取消订单
- 方便后续对账和退款处理
- 订单详情页明确显示「已取消」状态

## 2. 订单分配逻辑

### 2.1 接单模式 (主要)

商户可以主动接取未分配的订单。

*   **订单池**: 所有支付成功的订单进入 "待接单" 池。
*   **展示**: 商户端展示所有待接单的订单（可按楼栋筛选）。
*   **接单**: 商户点击 "接单"，系统检查订单状态并绑定商户 ID。
*   **归属**: 接单成功后，订单状态变更，生成打印任务归属于该商户。

### 2.2 派单模式 (辅助)
- **场景**: 订单长时间无人接单，或指定商户服务。
- **操作**: 管理员在后台手动将订单分配给指定商户。
- **通知**: 系统推送通知给被指派的商户。

## 3. 商户作业流程

### 3.1 商户认证方式
- 商户使用 `x-api-key` 请求头进行 API 认证
- API Key 在创建商户时自动生成（32字节十六进制字符串）
- 商户可以绑定微信账号用于接收通知

### 3.2 接单前
- 需通过资质审核 (营业执照、设备信息)。
- 保持在线状态 (通过商户端小程序保持活跃)。

### 3.3 接单后
1. **下载文件**: 从订单详情下载用户上传的文件 (PDF)。
2. **打印**: 使用本地设备打印。
3. **状态更新**: 
   - 点击"开始打印"更新任务状态为"打印中"
   - 点击"完成打印"更新任务状态为"已完成"
4. **订单流转**: 订单状态从"待接单"(1) → "打印中"(2) → "已完成"(3)
5. **派送完成**（可选）:
   - 上传派送完成图片
   - 标记订单为已完成

### 3.4 订单文件结构
- 一个订单可以包含多个文件
- 每个文件都有独立的打印参数（份数、颜色、单双面等）
- 打印任务（PrintTask）与订单文件一一对应
- 订单级打印参数已迁移至 OrderFile 表（保留字段用于兼容旧数据）

# 第二部分：技术调度架构 (Dispatch 模块)

此部分对应后端 `src/modules/dispatch` 模块及 `PrintEase-dispatch` 客户端的实现。

## 1. 模块职责
- **商户调度服务**: 处理商户接单、任务管理、订单完成等业务逻辑
- **打印任务管理**: 管理打印任务的生命周期
- **派送管理**: 处理订单派送相关功能
- **技术调度（预留）**: 云印节点注册、认证、心跳保活、自动打印任务分配

## 2. 系统架构

```
                        ┌─────────────────┐
                        │  商户端小程序    │
                        ├─────────────────┤
                        │ - 接单大厅      │
                        │ - 订单管理      │
                        │ - 任务处理      │
                        │ - 派送上传      │
                        └─────────────────┘
                                 ▲
                                 │ x-api-key 认证
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│                        印易后台 (Dispatch Module)                  │
├─────────────────────────────────────────────────────────────────┤
│  ┌──────────────────────┐  ┌──────────────────────┐            │
│  │ MerchantDispatchSvc  │  │ PrintTaskService    │            │
│  │ (商户调度服务)        │  │ (打印任务服务)       │            │
│  └──────────────────────┘  └──────────────────────┘            │
│  ┌──────────────────────┐  ┌──────────────────────┐            │
│  │ DeliveryService      │  │ OrderDispatchService │            │
│  │ (派送服务)            │  │ (订单调度服务)       │            │
│  └──────────────────────┘  └──────────────────────┘            │
└─────────────────────────────────────────────────────────────────┘
```

## 4. API 接口设计

### 4.1 商户认证
商户使用 `x-api-key` 请求头进行认证，无需 JWT Token。

### 4.2 商户信息管理
- `GET /api/merchant/tasks/profile`: 获取商户信息
- `PUT /api/merchant/tasks/profile`: 更新商户信息
- `GET /api/merchant/tasks/stats`: 获取商户统计信息
- `POST /api/merchant/tasks/bind-wechat`: 绑定微信
- `DELETE /api/merchant/tasks/bind-wechat`: 解除微信绑定

### 4.3 商户任务相关
- `GET /api/merchant/tasks/unassigned`: 获取待接单列表（支持分页、楼栋筛选）
- `POST /api/merchant/tasks/:id/grab`: 商户接单
- `POST /api/merchant/tasks/:id/cancel`: 取消接单（释放订单）
- `GET /api/merchant/tasks`: 获取商户的打印任务列表
- `GET /api/merchant/tasks/grouped`: 获取商户的打印任务列表（按订单分组）
- `GET /api/merchant/tasks/pending`: 获取待处理的打印任务
- `GET /api/merchant/tasks/:id`: 获取打印任务详情

### 4.4 任务操作
- `PUT /api/merchant/tasks/:id/start`: 开始打印任务
- `PUT /api/merchant/tasks/:id/complete`: 完成打印任务
- `POST /api/merchant/tasks/:id/force-complete`: 强制完成打印任务并同步订单
- `POST /api/merchant/tasks/:id/reassign`: 重新下发打印任务
- `PUT /api/merchant/tasks/:id/fail`: 标记打印任务失败

### 4.5 订单级操作
- `PUT /api/merchant/tasks/orders/:orderId/start-all`: 开始订单的所有打印任务
- `POST /api/merchant/tasks/orders/:orderId/force-complete-all`: 强制完成订单的所有打印任务
- `POST /api/merchant/tasks/:orderId/upload-image`: 上传派送完成图片（URL方式）
- `POST /api/merchant/tasks/:orderId/upload-delivery-image`: 上传派送完成图片文件
- `POST /api/merchant/tasks/:orderId/complete`: 完成订单

### 4.6 订单权限控制
- 普通用户只能查看和操作自己的订单
- 商户可以查看和操作分配给自己的订单
- 管理员可以查看和操作所有订单
- 订单详情接口支持商户和管理员查看任意订单
