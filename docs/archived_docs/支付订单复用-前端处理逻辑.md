# 支付订单复用 - 前端处理逻辑

## 概述

本文档描述了 PrintEase 印易项目中支付订单复用的前端处理逻辑。

**重要说明：支付订单复用的核心逻辑完全在后端实现，前端代码不需要做任何修改！**

## 前端工作流程

### 完整支付流程

```
用户在订单详情页点击"立即支付"
        ↓
前端调用 createPayment API
        ↓
    后端处理（复用或创建新支付）
        ↓
后端返回 payUrl 和 tradeNo
        ↓
前端跳转到支付页面
        ↓
展示支付二维码
        ↓
用户扫码支付
        ↓
用户点击"我已支付"查询状态
        ↓
轮询或刷新订单状态
```

## 涉及的前端文件

### 1. 订单详情页 (`pages/order/detail.vue`)

**核心功能：**
- 展示订单信息
- 提供"立即支付"按钮
- 提供"刷新订单状态"按钮

**关键代码片段：**

```typescript
async function goToPay() {
  if (!order.value) return
  
  try {
    uni.showLoading({ title: '创建支付中...' })
    // 调用后端 API
    const result = await createPayment(orderId.value)
    uni.hideLoading()
    
    if (result.payUrl) {
      // 跳转到支付页面
      uni.navigateTo({
        url: `/pages/pay/index?payUrl=${encodeURIComponent(result.payUrl)}&orderId=${orderId.value}`
      })
    }
  } catch (error) {
    uni.hideLoading()
    console.error('创建支付失败', error)
    uni.showToast({
      title: '创建支付失败',
      icon: 'none'
    })
  }
}
```

### 2. 支付页面 (`pages/pay/index.vue`)

**核心功能：**
- 展示支付二维码
- 提供"打开支付页面"按钮
- 提供"我已支付，查询状态"按钮

**关键代码片段：**

```typescript
function openPayPage() {
  if (!payUrl.value) return
  
  // 打开支付页面 webview
  uni.navigateTo({
    url: `/pages/webview/index?url=${encodeURIComponent(payUrl.value)}&orderId=${orderId.value}`
  })
}

function checkPaymentStatus() {
  if (!orderId.value) return
  
  uni.showLoading({ title: '查询中...' })
  
  // 调用后端 API 刷新订单状态
  refreshOrderStatus(orderId.value).then((result) => {
    uni.hideLoading()
    
    if (result.status === 1) {
      uni.showToast({
        title: '支付成功！',
        icon: 'success'
      })
      setTimeout(() => {
        uni.navigateBack()
      }, 1500)
    } else if (result.status === 0) {
      uni.showToast({
        title: '尚未检测到支付，请稍后再试',
        icon: 'none'
      })
    } else {
      uni.showToast({
        title: '订单状态已变更',
        icon: 'none'
      })
      setTimeout(() => {
        uni.navigateBack()
      }, 1500)
    }
  }).catch(() => {
    uni.hideLoading()
    uni.showToast({
      title: '查询失败',
      icon: 'none'
    })
  })
}
```

### 3. API 接口文件 (`api/order.ts`)

**关键接口：**

```typescript
// 创建支付
export function createPayment(orderId: string) {
  return request<{ tradeNo: string; payUrl: string }>({
    url: `/orders/${orderId}/payment`,
    method: 'POST'
  })
}

// 刷新订单状态
export function refreshOrderStatus(orderId: string) {
  return request<OrderInfo>({
    url: `/orders/${orderId}/status`,
    method: 'POST'
  })
}
```

## 为什么前端不需要修改

### 1. 逻辑透明性

- 支付订单复用逻辑完全在后端处理
- 前端只负责调用 API 和展示结果
- 后端返回的数据格式保持不变

### 2. API 接口不变

- 创建支付接口：`POST /api/orders/:id/payment`
- 返回格式：`{ tradeNo: string; payUrl: string }`
- 前端无需关心后端是复用还是新创建

### 3. 用户体验一致

- 用户操作流程不变
- 支付页面展示不变
- 状态查询方式不变

## 注意事项

### 1. 无需前端修改

- 支付订单复用是后端优化
- 前端代码保持原样
- 无需重新编译或发布前端

### 2. API 调用时机

- 每次用户点击"立即支付"都会调用后端 API
- 后端会自动判断是复用还是创建新支付
- 前端不需要做任何缓存或状态管理

### 3. 错误处理

- 前端保持原有的错误处理逻辑
- 后端会返回适当的错误信息
- 用户体验不受影响

## 测试建议

### 1. 正常支付流程测试

1. 创建新订单
2. 点击"立即支付"
3. 观察后端日志，确认创建了新的支付信息
4. 记录 `mpayCreatedAt` 时间

### 2. 复用支付流程测试

1. 在30分钟内，再次点击"立即支付"
2. 观察后端日志，确认复用了现有支付信息
3. 检查是否使用了相同的 `tradeNo` 和 `payUrl`

### 3. 过期支付流程测试

1. 等待超过30分钟
2. 再次点击"立即支付"
3. 观察后端日志，确认清除了旧的支付信息
4. 确认创建了新的支付信息

## 总结

- **前端不需要修改**：所有复用逻辑在后端实现
- **API 接口不变**：返回格式保持一致
- **用户体验一致**：操作流程没有变化
- **后端负责处理**：复用、过期、创建等逻辑

前端只需要按照原来的方式调用 API 即可！
