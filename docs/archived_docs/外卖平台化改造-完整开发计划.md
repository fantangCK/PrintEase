# 外卖平台化改造 - 完整开发计划

## 1. 项目概述

### 1.1 改造目标

将 PrintEase 印易项目从简单的自助打印系统改造为类似外卖平台的完整生态系统，包含：

- **用户端**：下单、支付、查看订单
- **商户端**：接单、打印、上传完成照片
- **管理端**：订单管理、用户管理、商户管理、价格管理、公告管理

### 1.2 核心功能（重点）

#### 🎯 必须优先实现的核心功能

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **1. 多角色身份体系** | P0 | 用户、商户、管理员三种身份，通过 role 字段区分 |
| **2. 管理员和商户认证** | P0 | 管理员和商户使用密钥/权限系统认证 |
| **3. 我的页面增加管理员入口** | P0 | 我的页面增加"管理员设置"按钮 |
| **4. 公告移至管理员页面** | P0 | 公告从首页隐藏，只在管理员页面可见和管理 |
| **5. 商户接单功能** | P0 | 商户可以接单/接单 |
| **6. 管理员接单+管理订单** | P0 | 管理员不仅可以接单，还可以管理所有订单 |
| **7. 打印完成照片上传** | P0 | 商户打印完成后，必须上传1-3张照片证明完成 |
| **8. 价格体系独立化** | P1 | 所有打印价格单独配置管理 |
| **9. 文件转换和覆盖率计算** | P1 | 上传文件自动转PDF，自动计算页面覆盖率 |

## 4. 功能模块详细设计

### 4.1 文件转换和覆盖率计算模块

#### 功能描述
- 支持多种文件格式转换为PDF（Word、Excel、PPT、图片等）
- 自动计算PDF每页的内容覆盖率
- 计算平均覆盖率
- 支持异步处理，不阻塞用户上传
- 提供处理进度查询
- 处理失败时提供错误信息

#### 文件格式支持

| 格式 | 扩展名 | 转换方式 |
|------|--------|----------|
| Word | .doc, .docx | LibreOffice / Office Online |
| Excel | .xls, .xlsx | LibreOffice / Office Online |
| PowerPoint | .ppt, .pptx | LibreOffice / Office Online |
| 图片 | .jpg, .jpeg, .png, .bmp, .tiff | ImageMagick / PIL |
| PDF | .pdf | 直接处理 |

#### 覆盖率计算算法

**覆盖率定义**：页面中有内容的区域占整个页面的百分比

**计算方法**：
1. 将PDF每页转换为图片
2. 对图片进行二值化处理（黑白）
3. 统计非白色像素数量
4. 计算覆盖率 = (非白色像素数 / 总像素数) × 100%

**精度控制**：
- 采样率：150 DPI（可配置）
- 覆盖率保留2位小数

#### API 接口

```
POST   /api/files/:id/convert           # 触发文件转换和覆盖率计算
GET    /api/files/:id/processing-status  # 查询处理状态
GET    /api/files/:id/coverage           # 获取覆盖率数据
```

#### 异步处理流程

```
用户上传文件
    ↓
创建 file_processing 记录（状态：待处理）
    ↓
加入异步处理队列
    ↓
立即返回给用户（提示处理中）
    ↓
后台Worker从队列获取任务
    ↓
更新状态为：处理中
    ↓
转换文件为PDF
    ↓
计算每页覆盖率
    ↓
计算平均覆盖率
    ↓
保存结果到数据库
    ↓
更新状态为：已完成
```

#### 覆盖率数据结构

```json
{
  "totalPages": 5,
  "averageCoverage": 45.23,
  "pageCoverage": [
    { "page": 1, "coverage": 38.50 },
    { "page": 2, "coverage": 52.30 },
    { "page": 3, "coverage": 41.80 },

```

#### 技术实现方案

**方案一：LibreOffice + Python（推荐）**
- 文件转换：LibreOffice UNO API
- 图片处理：Pillow (PIL)
- 覆盖率计算：NumPy + OpenCV
- 异步队列：Celery + Redis

**方案二：Node.js 纯方案**
- 文件转换：unoconv (Node.js封装)
- 图片处理：sharp
- 覆盖率计算：canvas
- 异步队列：Bull + Redis

#### 数据库操作
```typescript
// 计算订单价格
async calculatePrice(params: CalculatePriceDto): Promise<number> {
  const config = await this.priceConfigRepository.findOne({
    where: {
      paperSize: params.paperSize,
      colorType: params.colorType,
      doubleSided: params.doubleSided,
      printQuality: params.printQuality || PrintQuality.NORMAL,
      status: 1,
    },
  });

  if (!config) {
    throw new BadRequestException('未找到对应的价格配置');
  }

  const basePrice = config.pricePerPage * params.totalPages * params.copies;
  const deliveryFee = basePrice >= config.minOrderAmount ? 0 : config.deliveryFee;
  
  return basePrice + deliveryFee;
}
```

### 4.5 多角色权限模块

#### 角色定义

#### 权限守卫

```typescript
// roles.guard.ts
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    
    if (!requiredRoles) {
      return true;
    }
    
    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.some((role) => user.role === role);
  }
}

// 使用示例
```

## 7. 技术实现要点

### 7.1 文件转换技术

#### 文件格式转换
- **Word/Excel/PPT**: 使用 LibreOffice UNO API 或 Office Online API
- **图片**: 使用 ImageMagick 或 Pillow (PIL) 转换
- **PDF**: 直接使用，无需转换

#### 覆盖率计算技术栈
- **推荐方案**: Python + Pillow + NumPy + OpenCV
  - PDF转图片: pdf2image
  - 图片处理: Pillow
  - 数值计算: NumPy
  - 高级图像处理: OpenCV

- **备选方案**: Node.js + sharp + canvas
  - PDF转图片: pdf-poppler
  - 图片处理: sharp
  - Canvas操作: canvas

#### 异步队列技术
- **推荐方案**: Redis + Bull (Node.js)
  - 成熟稳定，生态完善
  - 与 NestJS 集成良好
  - 支持任务优先级、重试、延迟等

- **备选方案**: Redis + Celery (Python)
  - Python生态完善
  - 适合科学计算任务
  - 需要额外维护 Python Worker

### 7.2 订单分配策略

#### 方案一：接单模式
- 所有待接单订单对所有商户可见
- 商户主动接单
- 先到先得

#### 方案二：分配模式
- 管理员手动分配订单
- 可以根据商户位置、评分等因素分配

#### 方案三：混合模式（推荐）
- 支持接单和分配两种方式
- 管理员可以优先分配
- 未分配的订单进入接单池

### 7.3 照片存储方案

#### 方案一：本地存储
- 存储在服务器本地文件系统
- 通过静态文件服务访问
- 简单，成本低

#### 方案二：云存储（推荐）
- 使用阿里云 OSS / 腾讯云 COS / AWS S3
- 高可用，CDN 加速
- 可扩展性好

### 7.4 实时通知方案

#### 方案一：轮询
- 商户端定期轮询待接单订单
- 实现简单
- 实时性稍差

#### 方案二：WebSocket（推荐）
- 使用 WebSocket 实时推送
- 实时性好
- 实现稍复杂

## 8. 风险评估和应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 文件格式转换失败率高 | 高 | 中 | 提供多种转换方案，异常处理完善，用户可手动上传PDF |
| 覆盖率计算准确率不够 | 中 | 中 | 多种算法对比验证，持续优化，允许人工调整 |
| 异步处理队列积压 | 高 | 中 | 队列监控，多Worker扩容，任务优先级设置 |
| 商户端和用户端代码复用度低 | 中 | 高 | 提前规划代码结构，提取公共组件 |
| 订单并发接单冲突 | 高 | 中 | 使用数据库乐观锁/悲观锁 |
| 照片存储成本高 | 中 | 中 | 图片压缩，定期清理 |
| 开发周期超预期 | 高 | 中 | 优先开发核心功能，非核心功能可延后 |
| 数据库性能问题 | 高 | 低 | 合理设计索引，必要时分库分表 |
