# 跨平台小程序通用基础规范
## 一、核心执行原则
1. 所有代码必须遵循「一次编写，多端适配」原则，通过条件编译处理平台差异，禁止重复编写功能相同的代码
2. 生成的项目必须兼容对应跨端框架的最新版本，可直接在对应平台开发者工具中编译运行，无语法错误
3. 严格遵循各平台官方开发规范，不使用各平台已废弃的API与配置项
4. 公共逻辑、通用组件、工具函数必须统一封装，禁止多端重复实现

## 二、跨端项目目录结构规范
必须生成统一的跨端项目目录结构，严格遵循以下层级：
├── babel.config.js        // babel配置
├── tsconfig.json          // TS配置（使用TS时必备）
├── package.json           // 项目依赖配置
├── project.config.json    // 多平台项目配置
├── manifest.json          // 跨端框架应用配置（uni-app/Taro）
├── src/                   // 项目源码主目录
│   ├── app.js/ts          // 应用入口文件
│   ├── app.vue            // 应用根组件
│   ├── pages/             // 主包页面目录
│   │   └── [页面名]/      // 页面对应文件夹
│   ├── pages.json         // 全局页面路由与窗口配置
│   ├── components/        // 全局通用组件目录
│   ├── utils/             // 工具函数目录
│   ├── api/               // 接口请求管理目录
│   ├── static/            // 静态资源目录
│   │   ├── images/        // 图片资源
│   │   └── icons/         // 图标资源
│   ├── store/             // 全局状态管理目录
│   └── .trae/             // TRAE项目专属Skill与规则目录
└── dist/                  // 编译输出目录

## 三、跨端命名与代码规范
### 3.1 统一命名规则
1. 文件夹命名：全小写，多个单词用连字符`-`连接，禁止使用中文、特殊字符
2. 变量/函数命名：小驼峰命名法，函数必须以动词开头，语义化命名
3. 常量命名：全大写，多个单词用下划线`_`连接
4. 组件命名：大驼峰命名法，如`GoodsCard`、`SearchBar`，语义化明确
5. 样式类名：全小写，多个单词用连字符`-`连接，使用BEM命名规范可选

### 3.2 跨端代码适配规范
1. 平台差异必须使用对应框架的条件编译语法处理，禁止使用运行时环境判断做适配
2. 条件编译标准语法：
  // #ifdef MP-WEIXIN
   微信小程序专属代码
   // #endif

   // #ifdef MP-TOUTIAO
   抖音小程序专属代码
   // #endif

   // #ifdef MP-ALIPAY
   支付宝小程序专属代码
   // #endif

   // #ifdef MP-BAIDU
   百度智能小程序专属代码
   // #endif
   3. 各平台通用API必须做统一封装，抹平平台API差异，对外暴露统一的调用方法
4. 样式适配必须使用响应式单位，优先使用rpx，禁止使用固定px做全屏适配
5. 组件必须做平台兼容处理，一个组件同时适配多平台，禁止为同一功能创建多个平台专属组件

## 四、跨端接口与状态管理规范
1. 所有网络请求必须统一封装，抹平各平台网络请求API的差异，统一处理请求/响应拦截、错误处理、加载状态
2. 接口地址必须按业务模块统一管理，支持多环境切换（开发/测试/生产），禁止在页面中硬编码接口地址
3. 全局状态管理必须使用对应框架推荐的方案（如Pinia、Vuex、Redux），禁止通过页面栈、全局变量传递数据
4. 本地存储必须统一封装，抹平各平台存储API差异，统一数据加密、过期时间管理

## 五、各平台核心差异适配对照表
| 适配维度 | 微信小程序 | 抖音小程序 | 支付宝小程序 | 百度智能小程序 |
|---------|-----------|-----------|-------------|----------------|
| 模板语言 | WXML | TTML | AXML | Swan |
| 样式语言 | WXSS | TSS | ACSS | 标准CSS |
| API前缀 | wx. | tt. | my. | swan. |
| 主包限制 | 2MB | 2MB | 2MB | 2MB |
| 总包限制 | 16MB | 16MB | 16MB | 16MB |
| 事件绑定 | bind:tap | bind:tap | onTap | bind:tap |
| 授权机制 | scope权限体系 | scope权限体系 | 权限申请体系 | scope权限体系 |
| 核心特色 | 社交能力 | 视频/直播能力 | 支付/商业能力 | AI能力 |

## 六、执行要求
1. 所有跨端小程序项目必须优先执行本规范，生成符合标准的项目结构
2. 处理平台差异时，必须优先使用条件编译，禁止运行时判断导致的冗余代码
3. 所有生成的代码必须在对应平台开发者工具中完成编译测试，无兼容性问题
4. 当平台规则更新时，必须同步更新本规范中的适配规则
